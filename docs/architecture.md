# Neptune v0.3 Architecture

## Status

Initial scaffold, 2026-06-13.

`neptune_v0.3` is a clean reconstruction of the active Neptune ROI-bank gamma
workflow. It is not a wholesale copy of `neptune_iwae`. Code is migrated only
when it has a clear package boundary, tests, and a current role in the active
pipeline.

The importable Python package is named `neptune_v03` because dots are not valid
inside Python package identifiers.

## Goals

- Keep the active microtube ROI-bank gamma loop reproducible.
- Separate research configuration from runtime artifacts.
- Make the package installable, testable, and understandable enough for public
  source release.
- Preserve the current scientifically relevant behavior before optimizing or
  generalizing it.

## Non-Goals

- Preserve every historical `neptune_iwae` experiment variant.
- Copy large training entrypoints before their contracts are made explicit.
- Hide runtime outputs, checkpoints, ROI banks, or SLURM logs in source
  directories.
- Introduce abstractions for workflows that do not yet have a second use case.

## Package Boundaries

The intended module boundaries are:

| Module | Responsibility |
| --- | --- |
| `neptune_v03.config` | Load base configs, apply composable overrides, and materialize resolved run configs. |
| `neptune_v03.data` | Raw TIFF access, camera backward conversion, domain crops, and bounded frame readers. |
| `neptune_v03.peak` | Peak harvest and initial phase/gamma bootstrap contracts from raw TIFF data. |
| `neptune_v03.optics` | PSF, Zernike/gamma coefficients, field-dependent maps, and projection primitives. |
| `neptune_v03.localization` | Localizer model wrappers, output decoding, and posterior parameter extraction. |
| `neptune_v03.roi_library` | ROI-bank HDF5 storage, ROI candidate geometry, FOV-balanced selection, and minimal raw-TIFF fixed library construction through an injected inference function. |
| `neptune_v03.gamma_update` | Detached posterior sampling and gamma-only physics updates on fixed ROI libraries. |
| `neptune_v03.training` | Epoch loop, update schedule, checkpointing, and feedback-map handoff. |
| `neptune_v03.diagnostics` | Gamma update monitor summaries now; overlay figures and reconstruction monitors later. |

`config`, `runtime`, `launch`, `peak`, `optics`,
`diagnostics.gamma_update_monitor`, the initial `roi_library` HDF5 IO,
candidate geometry, selection, raw-TIFF builder layers, and the native
microtube TIFF training-batch provider are implemented. `localization` now
includes a native residual encoder-decoder production localizer boundary. The
remaining boundaries are documented now so future migration does not recreate
the large mixed-purpose modules from `neptune_iwae`.

## Configuration Strategy

The current `neptune_iwae` tree stores experiment variants as copied JSON and
SLURM files. v0.3 uses one base YAML config plus small overrides:

- `configs/microtube_base.yaml`: shared microtube ROI-bank gamma configuration.
- `configs/overrides/gamma_start50_interval10.yaml`: active formal schedule
  kept under the original scaffold filename. It now materializes the current
  default route: start epoch 30, interval 5, 128 px ROI, 25 posterior samples,
  100 gamma steps, and 20 fixed held-out ROI.
- `configs/overrides/gamma_start25.yaml`: early-update ablation.
- `configs/overrides/gamma_start50.yaml`: 50-epoch update ablation.
- `configs/overrides/smoke.yaml`: minimal local verification profile.

Resolved configs are generated by `python -m neptune_v03.config.materialize`
after installing the package in editable mode. For source-tree-only checks, use
`PYTHONPATH=src python -m neptune_v03.config.materialize`. Generated configs
belong in `output/` or another explicit run directory, not in source config
folders.

## Runtime Artifact Policy

- Durable source docs live in `docs/`.
- Reusable launch or diagnostic scripts live in `scripts/`.
- Generated runs, resolved configs, ROI banks, checkpoints, and figures live in
  `output/`.
- Logs live in `logs/`.
- Local temporary work and caches live in `.local/`.
- Large ROI-bank numeric data must use chunked HDF5, not CSV, JSON arrays, or
  per-emitter text files.

## Migration Rule

For each migrated subsystem:

1. Define the public contract in docs or tests.
2. Add focused tests before moving behavior.
3. Port the smallest useful implementation slice.
4. Verify against a small smoke input.
5. Only then wire the subsystem into the training loop.

This keeps v0.3 usable at every step and prevents another experiment-heavy tree
from forming.

## Next Migration Order

The current priority is to preserve the working physical-model loop before
porting large training code.

Completed:

- `diagnostics.gamma_update_monitor`: read-only monitor contract from
  `neptune_iwae/scripts/diagnostics/gamma_update_monitor.py`.
- `roi_library.raw_tiff_builder`: minimal fixed ROI-library construction from
  TIFF/array frames through an injected inference function, with optional HDF5
  export for offline diagnostics.
- `runtime` and `launch`: run directories, manifests, stage status, artifact
  registry, local command generation, and deterministic SLURM script writing.
- `peak.contract`: standard output contract for the active peak SLURM stage,
  including harvest, NAT diagnostics, coeff-map/zmap exports, and
  `peak_nat_zmap_summary.json`.
- `peak.pipeline`: orchestration boundary that connects peak harvest,
  NAT-LM fitting, NCC summarization, and coeff-map/zmap export backend calls
  into the standard contract.
- `peak.backend`: thin default backend delegating to split peak modules.
- `peak.harvest`: raw-TIFF harvest, local-maximum peak selection, distance
  filtering, torch harvest payload export, and peak harvest summaries.
- `peak.diagnostics`: raw-patch diagnostics, lightweight LM-style Gaussian
  local fitting, alternating gamma-field regression, raw/reconstruction
  MSE/NCC metrics, NCC filter masks, diagnostics payload export, and NCC
  summarization.
- `peak.export`: lightweight full-ROI coefficient stack and provisional scalar
  zmap export behind the default peak pipeline contract, now using the shared
  `optics` gamma-to-map boundary.
- `optics.nat_field`: order1 NAT field config, FOV coordinate conversion,
  gamma-to-Zernike coefficient evaluation, and full-ROI coefficient stack
  generation.
- `optics.renderer`: differentiable Gaussian PSF renderer adapter for CPU smoke
  tests and for the current lightweight peak diagnostics path. The
  high-fidelity vector-PSF NAT optimizer and historical figure/report pack
  remain separate migration steps.

Next:

1. `gamma_update.posterior_sampling`: re-run the current localizer on selected
   fixed ROI records and sample detached posterior emitters.
2. `gamma_update.objective`: implement over-cut cropped importance wake
   Poisson NLL and gamma-only optimization.
3. `peak.diagnostics` / `peak.export`: migrate high-fidelity vector-PSF NAT
   fitting and the richer visual report pack where needed.
4. `diagnostics.reconstruction`: raw TIFF/photon ROI versus projected
   reconstruction figures and zmap/gamma before-after figures.
5. `training.loop`: connect the epoch hook, fixed ROI cache, fixed held-out
   samples, feedback maps, checkpoints, and SLURM entry points.

Do not migrate old per-step raw/NAT wake updates into the default v0.3 path.
They remain ablations, not the active route.
